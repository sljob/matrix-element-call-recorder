# Matrix Element Call + E2EE Recorder

[English README](README.md)

Запись конференций браузерным клиентом Chromium + Puppeteer + FFmpeg. В этой версии встроенные кодированные исходники заменены читаемыми файлами из **sljob/matrix-element-call-recorder**. Рекордер участвует в звонке как Matrix-клиент с E2EE-ключами, а не взламывает шифрование.

## Что умеет проект

Это самостоятельная реализация записи **аудио и видео** конференций Element Call/MatrixRTC при E2EE. Записывающий бот входит в звонок как обычный участник с доступом к ключам, используя headless Chromium; захват и обработку выполняют Puppeteer и FFmpeg. Это **не встроенная функция Element Call** и не обход шифрования. Подробнее об архитектуре и развитии проекта — в [моём обсуждении запроса на запись Element Call #283](https://github.com/element-hq/element-call/issues/283).

- **Быстрый запуск.** По наблюдениям автора, после нажатия «Начать запись» бот обычно присоединяется к звонку и начинает запись примерно через **3–5 секунд**. Это не гарантированный SLA: время зависит от нагрузки и готовности компонентов.
- **Кто запускает.** Запись может запустить создатель комнаты или участник с достаточным Matrix Power Level; серверный администратор Synapse может запустить её, если находится в комнате с конференцией. Порог комнаты задаётся в `answers.conf`: `RECORDING_MIN_POWER_LEVEL=50` по умолчанию. Не каждый пользователь с названием роли «админ» автоматически обладает нужным уровнем: проверяются фактические права.
- **Публикация и просмотр.** После завершения и обработки файл автоматически попадает в архив записей с привязкой к комнате. Рядом с кнопкой записи есть ссылка **«Записи»**, открывающая `/recordings/` в новой вкладке. Если требуется вход, он осуществляется **той же учётной записью Matrix**, что и в Element; отдельного аккаунта архива нет. Это не обещание автоматического SSO без повторного ввода учётных данных.
- **Разграничение доступа.** Администратор комнаты видит и скачивает записи **только доступных ему комнат**, в которых он состоит и имеет необходимый Power Level. Администратор сервера Synapse имеет доступ ко всем записям. Система проверяет права и при открытии списка, и при обращении к файлам; одна ссылка сама по себе не даёт доступ. Доступ зависит от текущих прав, а не только от того, кто инициировал запись.
- **Параллельная запись.** Пул независимых записывающих процессов позволяет писать разные комнаты одновременно; число работников задаётся `RECORDING_WORKERS` (пример: 4). Работа проверялась автором на развёрнутом сервере, но производительность зависит от CPU, памяти и числа участников.
- **Поиск сотрудников по отображаемому имени.** В стандартной конфигурации Synapse поиск всех пользователей по отображаемому имени может быть ограничен; установщик проекта явно включает `user_directory` с `search_all_users: true` и `prefer_local_users: true`. Это решение расширяет обнаруживаемость учётных записей — оцените его с точки зрения приватности и политики организации.

### Комната «Сотрудники» — отдельно или при установке

Справочник можно установить **отдельно** на уже работающий сервер без него (`addons/staff-directory/standalone.sh`) либо выбрать при **первой установке нового сервера**. В `answers.conf`, созданном из `answers.example`, укажите:

```ini
STAFF_DIRECTORY_ENABLED=true
```

Для установки **без** справочника установите `STAFF_DIRECTORY_ENABLED=false` (значение в шаблоне) или не указывайте ключ. Токен администратора Synapse запрашивается при установке дополнения и **не помещается** в файл ответов. На работающем Cloud переустанавливать основной стек и менять `answers.conf` не нужно. Установка создаёт одного бота и одну приватную комнату; отдельно добавляются только приглашённые и присоединившиеся сотрудники.

**Точность статусов.** По наблюдениям на наших серверах Matrix presence обычно показывает работу в Element Desktop и Element Web. В проверенном сценарии Element X (мобильный клиент) presence возвращал `offline` даже при активности и корректно обнаруживался как «Занят» во время звонка через LiveKit. Поэтому для случая `offline` справочник показывает **«Недавно в сети»** при обращении любого устройства пользователя к Synapse за последние 10 минут. Это не точный «онлайн», не показатель разблокированного экрана и не доказательство работы с телефона: возможна фоновая синхронизация. Подпись **«последнее обращение: мобильный / ПК»** основана на данных последнего устройства и его User-Agent; если тип установить нельзя — так и написано. Особенность presence Element X описана разработчикам; [обсуждение записи #283](https://github.com/element-hq/element-call/issues/283) посвящено записи и **не является отчётом об этой ошибке presence**.

Проект разработан примерно за три месяца; опыт работы автора с Docker и Ubuntu на момент создания составлял чуть более года. Это открытое описание процесса, а не утверждение, что каждый фрагмент кода был написан исключительно ИИ или что какое-либо решение официально поддерживается Element/Matrix. Я горжусь результатом, но не заявляю непроверяемое мировое первенство или отсутствие других реализаций.

## Установка нового сервера

Нужен чистый Ubuntu. Это не обновление работающего сервера и не миграция языка. Для предварительной проверки нужны Python 3, OpenSSL и iproute2. Установщик устанавливает Docker/Compose при отсутствии, скачивает закреплённые образы и собирает авторские компоненты записи. Нужен доступ к GitHub, пакетным репозиториям и реестрам образов.

1. Выберите полный SHA коммита из 40 символов, в котором опубликован весь этот комплект.
2. Скачайте и просмотрите `install.sh` и `answers.example` из выбранного коммита.
3. Скопируйте шаблон в `/root/answers.conf`. Укажите `SOURCE_COMMIT`, домен, **локальный IP нового сервера** и пути к TLS-файлам. Пример домена/IP обязательно замените. Язык выбирается через `INSTALL_LANGUAGE=ru` или `en`; без параметра используется ru.
4. От root выполните:

```bash
chmod 700 ./install.sh
chmod 600 /root/answers.conf
set -o pipefail
bash ./install.sh --check /root/answers.conf 2>&1 | tee /root/install-check.log
# Только после успешной проверки:
bash ./install.sh --install /root/answers.conf 2>&1 | tee /root/install.log
```

Режим `--check` скачивает и проверяет исходники, затем запускает прежнюю предварительную проверку. Он может создать рядом с answers.conf файл с автоматически сгенерированными паролями: это не строго read-only режим. Сохраните этот закрытый файл для повторной попытки. Не публикуйте answers.conf, пароли, приватные ключи, дампы БД и профили рекордеров.

`SOURCE_COMMIT` принимает только полный SHA, не `main`, тег или короткий SHA. Все файлы скачиваются из одного коммита. В `installer/sources.json` указаны SHA256 файлов; весь комплект проверяется до запуска `installer/install.py`. Ошибка HTTPS, отсутствие файла или несовпадение хеша останавливают установку. Хеши защищают от повреждённого/несогласованного комплекта, но не являются независимой цифровой подписью. Выбранный коммит нужно просмотреть.

## Состав и настройки

Synapse, PostgreSQL, Element Web/Call, LiveKit, JWT service, Traefik, контроллер записи, пул рекордеров, закрытый портал записей и публикация MP4/MP3. Сохранена логика генерации конфигурации и исправлений приложенного установщика. `RECORDING_WORKERS` — 2 или 4. Закреплённые образы находятся в движке установки; не подменяйте их старыми несовместимыми тегами.

Язык кнопки записи и портала выбирает `INSTALL_LANGUAGE`. Штатный Element использует собственную настройку языка. Поиск сотрудников по отображаемому имени включён; импорт AD и постоянный список всех сотрудников не добавлены. Язык и SOURCE_COMMIT входят в отпечаток конфигурации: редактирование answers.conf и повторный запуск не являются поддерживаемой миграцией.

ПК должны достигать объявленного медиа-IP: UDP 7882, TCP 7881; для TURN — UDP 3479, TLS TCP 5350 и настроенный диапазон relay UDP 30000–30020. Проверьте маршрутизацию и обратный трафик. HTTPS не подтверждает работоспособность ICE/медиа. Настройте DNS, доверие CA на ПК и отдельно проверьте синхронизацию времени. Сохранена проверка локального LAN IP; схема публичного NAT требует отдельной конфигурации.

## Структура исходников

- `install.sh` — небольшой загрузчик и проверка файлов.
- `installer/install.py` — открытый движок установки, генерация конфигурации и прежние исправления.
- `src/` — финальные версии рекордера, контроллера, пула и портала.
- `config/record-button.js` — исходник кнопки записи.
- `locales/en.json` — английские переводы; русские строки остаются в исходниках.
- `installer/templates/` — исходные шаблоны, publisher, package.json/lock и вставка метаданных для существующих шагов исправления.
- `installer/compat/` — промежуточные совместимые версии из прежнего установщика; после них применяются финальные `src/`.
- `installer/sources.json` — перечень нужных файлов и их хешей.
- `tools/update-source-manifest.py` — пересчёт хешей после проверенных изменений.

Декодирования исходного кода из Base64 больше нет. В install.py остаются читаемые конфигурационные шаблоны, Dockerfile, тесты и исправления строк. Промежуточные templates/compat намеренно сохраняют порядок генерации прежнего установщика.

## Публикация в вашем GitHub

Скопируйте **всё содержимое ZIP в корень репозитория**, сохранив вложенные пути. В `GITHUB_PATHS.txt` указано: NEW — добавить, REPLACE — заменить. Сохраните существующие LICENSE, CONTRIBUTING и настройки issues. Комплект сам ничего не публикует в GitHub.

```bash
python3 tools/update-source-manifest.py
python3 tools/validate-sources.py
# Просмотрите diff, затем закоммитьте и отправьте весь комплект.
git rev-parse HEAD
```

Полученный полный SHA пользователи вписывают в свой приватный answers.conf. Не пытайтесь вписать SHA коммита в него самого: в answers.example специально оставлен заполнитель. Файлы и manifest публикуются одним коммитом. Пока комплект не загружен на GitHub, новый загрузчик не сможет работать с прежним коммитом: нужных файлов там нет.

Старый `config/index.html` не используется установщиком: HTML Element извлекается из закреплённого образа, затем вставляется кнопка. Не заменяйте исходники приватными файлами production-сервера.

## Справочник «Сотрудники» — 0.1.6

Опциональное серверное дополнение, без агентов на устройствах. Источники: Matrix presence, LiveKit и время последнего обращения локального устройства Synapse. Создаёт ОДНОГО неадминистративного бота и ОДНУ приватную комнату «Сотрудники» без E2EE. В списке — принявшие приглашение участники комнаты, не автоматически все пользователи сервера. Бот не должен вступать в другие чаты/конференции. Сообщения и реакции публикует только бот PL100. Администратор комнаты PL99 приглашает сотрудников, но не пишет и не меняет state с порогом100. Synapse admin/root полномочия не ограничиваются этими ACL.

### Новая установка сервера

В answers.conf до первого запуска выберите:
```ini
STAFF_DIRECTORY_ENABLED=false
```
`false` (или отсутствие ключа) — пропуск; `true` — установить дополнение после успешной готовности основного стека. Проверка выбора выполняется bootstrap install.sh ДО запуска основного engine; при --check бот/комната не создаются. DOMAIN/INSTALL_DIR берутся из answers. При установке запрашиваются подтверждение домена и admin access token скрытым вводом. Токен НЕ помещать в answers. Установка интерактивная. Требуются Python>=3.10, systemd>=250, systemd-creds/systemd-run/systemd-analyze. Неподходящая ОС не обновляется автоматически.

### Уже работающий сервер без справочника

Используйте `bash addons/staff-directory/install.sh` из полной локальной копии репозитория, либо отдельный автономный `standalone.sh` из той же папки. Не запускайте основной install.sh на production, не редактируйте неизменяемый answers.conf. Добавляются только каталоги /opt/matrix-staff-directory, /etc/matrix-staff-directory, /var/lib/matrix-staff-directory и три systemd службы. Основные контейнеры не перезапускаются, порты/compose/профиль не меняются. Нужны существующие compose.json, CA и сервисы synapse/jwt/livekit. Создание Matrix-аккаунта и комнаты не является транзакцией: при ошибке могут остаться новые сущности, ID сохраняются в encrypted progress.cred. Повторное развёртывание поверх настроенного экземпляра запрещено. Несколько независимых комнат/ботов на одном сервере не поддержаны.

### Статусы и последнее устройство

Занят — распознанный LiveKit ACTIVE; В сети/Отошёл — Matrix presence. Если presence offline/неизвестен, timestamp устройства <=600с даёт «Недавно в сети». После истечения окна при offline — «Не в сети (по Matrix)»; ошибки — неизвестно. При каждом статусе добавляется «последнее обращение: мобильный / ПК». Выбирается max(last_seen_ts) среди неудалённых обычных устройств; dehydration исключён. Тип — эвристика User-Agent, не display_name. При недостатке данных «не определено»; равные timestamps разных распознанных типов — «несколько типов устройств». Фоновая синхронизация считается обращением. Это НЕ устройство текущего звонка, не геолокация/удалёнка и не доказательство внимания человека.

Интервалы: publisher/presence=5с, LiveKit adapter=5с, устройства=15с; окно недавней активности=10мин. Доставка и Synapse могут добавлять задержку. Без гарантии мгновенного отклика. Пример нагрузки N пользователей: до12N presence+4N device запросов/мин плюс LiveKit. Публикация меняется при изменении результата или heartbeat15мин, а не каждые5с. Отметка старше20мин считается устаревшей. При большой группе/ошибках цикл удлиняется; оценивайте нагрузку до увеличения числа сотрудников. Службы работают от root; Docker-адаптер имеет root-equivalent доступ к Docker.

### Credentials и отключение

Токены bot/admin и LiveKit-секреты шифруются systemd host key (НЕ TPM). Только collector получает admin credential, publisher — bot/LiveKit. Это полноценный Synapse admin token, не read-only scope. Используйте отдельную сессию, которую можно отозвать. Root/захват сборщика позволяют получить секрет: encryption-at-rest не заменяет защиту хоста. Не копируйте .cred на другой сервер; ключ хоста хранится отдельно в /var/lib/systemd/credential.secret. config.json без токенов.

Отключение: `bash /opt/matrix-staff-directory/disable-addon.sh`. Только три службы, без удаления бота/комнаты/истории. Это НЕ полный откат Matrix. При ошибке не удаляйте каталоги и не запускайте весь стек заново.

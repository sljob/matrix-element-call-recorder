# E2EE Recorder — плагин для работающего сервера Element Call

Добавляет браузерную запись конференций Element Call со сквозным шифрованием
на сервер, который уже работает. Не меняет ваш compose-файл, статическую
конфигурацию Traefik, homeserver.yaml и образы вышестоящих сервисов.

Рекордер входит в звонок как обычный Matrix-клиент со своими E2EE-ключами
внутри headless Chromium; Puppeteer и FFmpeg снимают результат. Шифрование при
этом не обходится, и это не встроенная функция Element Call.

## Что добавляется

* кнопка в Element Web рядом с управлением звонком;
* <img width="609" height="67" alt="image" src="https://github.com/user-attachments/assets/28b929bb-a6e9-4846-9f2c-db76066cba3e" />

* архив записей на /recordings/ с авторизацией через Matrix;
* контроллер, портал, публикатор и N воркеров-рекордеров в отдельном
  compose-проекте recording-overlay;
* два роутера Traefik, опубликованных только через лейблы контейнеров.

## Требования

* работающий Matrix-стек с Element Web за Traefik;
* Traefik с **включённым docker-провайдером** и смонтированным
  /var/run/docker.sock. Лейблы — единственный механизм маршрутизации, который
  использует плагин. Если провайдер выключен или его Docker SDK старше
  минимального API демона, установщик теперь откажется работать вместо того,
  чтобы создать контейнеры без маршрутов;
* один или несколько существующих аккаунтов Matrix для рекордеров.
  Установщик никогда не создаёт аккаунты;
* около 2 ГБ ОЗУ и 2 vCPU на каждый воркер.

## Установка

1. Получить исходники и закрепить ядро рекордера:

       bash tools/fetch-upstream.sh

   Скрипт пишет vendor/SOURCE с коммитом и SHA256 каждого файла.
   Коммитить нужно этот файл, а не JavaScript.

2. Скопировать шаблон ответов и закрыть права:

       cp answers.example /root/answers-plugin.conf
       chmod 600 /root/answers-plugin.conf

3. Заполнить DOMAIN, PLUGIN_DIR, RECORDER_ACCOUNTS и RECORDER_PASSWORDS.
   Явно указать INSTALL_LANGUAGE — см. ниже.

4. Проверка без изменений, затем установка:

       bash install.sh --check   /root/answers-plugin.conf
       bash install.sh --install /root/answers-plugin.conf

## Язык интерфейса

INSTALL_LANGUAGE принимает ru или en и влияет на кнопку записи и на архив
записей. Язык самого Element не меняется.

Если ключа нет и установщик запущен в терминале, он спросит язык и запишет
ответ обратно в файл ответов, чтобы при повторных запусках и при --uninstall
вопрос не задавался снова. Если терминала нет (CI, вывод в файл), по
умолчанию берётся en с предупреждением. Неподдерживаемое значение вроде de
останавливает установку до сборки образов.

В предыдущих версиях каждый компонент молча подставлял ru — именно поэтому
при английской установке кнопки оказывались русскими.

## TLS: почему браузер показывает TRAEFIK DEFAULT CERT

Если у Traefik нет сертификата на домен и нет ACME-резолвера, роутер с
tls=true получает встроенный резервный сертификат Traefik. Импорт этого
сертификата в браузер не помогает: запрос обслуживается резервным
сертификатом раньше, чем учитывается доверие к вашим CA.

--check и --install опрашивают порт 443 с именем домена в SNI и сообщают,
какой сертификат реально отдаётся. Если это резервный, установщик печатает три
варианта решения и продолжает работу; сам он это исправить не может, потому
что конфигурация Traefik принадлежит хосту.

Три варианта:

* A — ACME: добавить резолвер в Traefik и указать TRAEFIK_CERTRESOLVER в
  ответах. Роутеры начнут использовать его напрямую.
* B — свой сертификат: смонтировать его в контейнер Traefik и объявить в
  динамической конфигурации:

      tls:
        stores:
          default:
            defaultCertificate:
              certFile: /certs/fullchain.pem
              keyFile: /certs/privkey.pem

* C — стенд с самоподписанным CA: создать CA, подписать сертификат на домен,
  затем применить B. Сертификат CA дополнительно указывается в TLS_CA_FILE,
  чтобы контейнеры плагина доверяли Synapse и Element Call.

## Маршрутизация

Создаются два роутера:

| Путь | Бэкенд | Приоритет |
|---|---|---|
| /recording и /recording/* | controller:8765 | 100 |
| /recordings и /recordings/* | portal:8899 | 90 |

Правило API — PathPrefix(/recording/) или Path(/recording), а не
PathPrefix(/recording). Короткая форма совпадает и с /recordings, поэтому
роутер API с более высоким приоритетом перехватывал архив и отдавал 404.
В 0.1.0 это был реальный дефект, здесь он исправлен.

## Права доступа

Два независимых порога по уровню мощности. Оба читаются из answers-файла, и
проверяет их бэкенд по реальному событию `m.room.power_levels` комнаты; проверка
в кнопке нужна только для внятного сообщения и никогда не считается доверенной.

| Параметр | По умолчанию | Что регулирует |
|---|---|---|
| `RECORDING_MIN_POWER_LEVEL` | 50 | кто может начать и остановить запись |
| `RECORDINGS_MIN_POWER_LEVEL` | 50 | кто может видеть и скачивать готовые записи |

`50` — администратор комнаты (столько получает создатель комнаты), `0` — любой
участник. Администраторы сервера Synapse (`admin: true` в users admin API)
всегда видят все записи независимо от членства в комнатах.

Оба порога проверяются на сервере:

* `/api/record/start` и `/api/record/stop` в контроллере — членство плюс уровень
  мощности, а при недоступном Synapse ответ `503`, а не действие наугад;
* индекс архива и каждое скачивание `/files/...` в портале — чтобы скопированная
  ссылка не становилась правом доступа.

Сама кнопка записи видна всем участникам комнаты и ниже порога отвечает
всплывающим сообщением; чтобы её скрывать, нужна правка UI — Element Web
рендерит этот слот заголовка для всех участников.

## Маршрутизация через nginx вместо Traefik

Метки Traefik — режим по умолчанию и единственный, который установщик
настраивает сам. С nginx тоже работает: контракт — два префикса пути и одна
раздача статики, ничего специфичного для Traefik в нём нет.

```
/recording/  -> rec-controller:8765   (снять /recording)
/recordings/ -> rec-portal:8899       (снять /recordings)
/files/      -> rec-portal:8899       (старые абсолютные ссылки на скачивание)
```

Скопируйте `nginx.example.conf` в блок `server { }` вашего vhost Element и
перезагрузите nginx. Префикс снимает именно слэш в конце `proxy_pass`; без него
все вызовы API отдают 404. В отличие от Traefik, nginx не нужны приоритеты
маршрутов — он выбирает самый длинный совпавший префикс, — и не нужен
увеличенный `proxy_read_timeout`, потому что `/api/record/stop` сразу отвечает
`202`, а финализация идёт асинхронно.

Чтобы внешний прокси дотянулся до контейнеров, `PUBLISH_LOOPBACK_PORTS="true"`
(значение по умолчанию) публикует оба сервиса на `127.0.0.1:8765` и
`127.0.0.1:8899`. Поставьте `false`, если маршрутизируете только через метки
Traefik. Если nginx сам в контейнере, обращайтесь к `rec-controller:8765` и
`rec-portal:8899` по общей docker-сети вместо `127.0.0.1`.

## Проверка

    cd testbed
    docker compose -f compose.fake.yml up -d
    bash smoke.sh
    docker compose -f compose.fake.yml down

Smoke-тест проверяет обнаружение окружения, генерацию compose, вставку кнопки,
снятие префикса и отказ по чужому токену. Он не проверяет вход headless
Chromium в реальный E2EE-звонок — для этого нужны Synapse и LiveKit.
См. docs/TESTING.md.

## Удаление

    bash install.sh --uninstall /root/answers-plugin.conf

Контейнеры и роутеры удаляются, index.html восстанавливается из бэкапа,
сделанного перед первой установкой. Записи, профили и бэкапы остаются в
PLUGIN_DIR. Образы сохраняются намеренно: переустановка не должна заново
собирать 1.5 ГБ базового слоя Chromium.

## Известные ограничения

* Обновление образа Element Web заменяет index.html — нужен --reapply-ui.
* Рекордер виден в списке участников как обычный пользователь.
* Для Synapse нужна коллация C в PostgreSQL; это свойство сервера, плагин его
  не настраивает.

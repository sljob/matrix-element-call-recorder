# Проверка перед установкой и разрешение конфликтов

Установщик проверяет окружение **до** того, как что-либо соберёт или запустит.
Если найдено то, из-за чего запись не заработает, установка останавливается с
читаемым отчётом вместо «зелёной» установки, которая умирает на первой записи.

## Как запускать

```bash
bash install.sh --check /root/answers.env     # только проверка, ничего не меняется
bash install.sh --install /root/answers.env   # проверка, затем установка
```

`--check` возвращает код `2`, если есть блокеры. `--install` при блокерах
выходит с кодом `3` и не трогает сервер.

Осознанный обход блокеров — отдельный ключ, не связанный с `--yes`:

```bash
FORCE_INSTALL="true" bash install.sh --install /root/answers.env
```

## Уровни

| Уровень | Значение |
|---|---|
| `XX` блокер | запись гарантированно не заработает; установка остановлена |
| `!!` предупреждение | заработает, но, скорее всего, не так, как задумано |
| `..` к сведению | ожидаемый остаток прошлой установки, обрабатывается сам |
| `OK` проверено | всё в порядке |

## Что проверяется

### Учётные записи ботов

Главная проверка. Раньше установщик спрашивал «существует ли аккаунт», и этого
было мало: аккаунт мог существовать с другим паролем, проверка светилась
зелёным, установка проходила, а первая запись падала на `M_FORBIDDEN` внутри
воркера — там, где в логах контроллера ничего нет.

Теперь для каждого бота выполняется настоящий `POST /_matrix/client/v3/login`:

| Ситуация | Уровень |
|---|---|
| аккаунт есть, пароль из answers подходит | `OK` |
| аккаунт есть, пароль из answers не подходит | **блокер** |
| аккаунт есть, `RECORDER_BOT_PASSWORDS` пуст | **блокер** — пароль неизвестен |
| аккаунта нет, пароль задан | `!!` — будет создан |
| аккаунта нет, пароль пуст | **блокер** — не создать и не залогинить |
| бот совпадает с `ADMIN_USER` | **блокер** — бот не должен быть админом |
| у двух ботов одинаковый пароль | **блокер** |
| Synapse не ответил | `!!` |
| `429` (rate limit) | `!!` — проверка намеренно не блокирует |

`429` — предупреждение, а не блокер: проверка не должна создавать ту проблему,
которую ищет. Частые прогоны `--check` подряд могут упереться в лимит логинов.

### Порты

Проверяются `CONTROLLER_PORT`, `REC_HTTP_PORT` и по одному порту на воркер
(`RECORDER_BASE_PORT`, `+1` за каждого).

| Ситуация | Уровень |
|---|---|
| свободен | `OK` |
| занят своим контейнером `rec-*` | `..` — пересоздастся |
| занят чужим контейнером | **блокер**, с именем |
| занят процессом хоста | **блокер**, с именем и pid (`ss -lntpH`) |

### Сеть и компоненты

| Ситуация | Уровень |
|---|---|
| сети плагина нет | **блокер** |
| сети Element Web нет | `!!` — nginx в контейнере не увидит сервисы |
| контейнер Element Web не найден | **блокер** |
| Synapse не найден | `!!` — учётки не проверить |
| Element Call не найден | `!!` |

### Образы и остатки

| Ситуация | Уровень |
|---|---|
| контейнеры `rec-*` от прошлой установки | `..` |
| посторонние `rec-*` контейнеры (не наши имена) | `!!` |
| образы `recorder-plugin/*` других версий | `..` |
| больше 5 висячих образов | `!!` |

### Шаблоны

Установщик рендерит compose и nginx-сниппет во временный каталог и парсит
результат. Это ловит дефект в самом установщике до того, как он попадёт на диск.

| Ситуация | Уровень |
|---|---|
| шаблон падает с исключением | **блокер** |
| остались `{плейсхолдеры}` | **блокер** |
| compose не парсится как YAML | **блокер** |
| сервисов меньше двух | **блокер** |
| в compose остались ярлыки traefik | **блокер** |
| несбалансированные скобки в nginx | **блокер** |
| нет `proxy_pass` или маркеров блока | **блокер** |

### Ядро записи

| Ситуация | Уровень |
|---|---|
| `p63-observer.js` не найден | **блокер** |
| нет фиксов (`REC_USER`, `REC_PASS`, `ROOM_ID`, `OUT_FILE`, `-vsync cfr`, `/tmp/ffprogress.log`, `MAP ` с пробелом, `virtual_speaker.monitor`) | **блокер** — ядро из старой сборки |
| `vendor/` отличается от `src/recorder/` | `!!` — правки ушли в один файл |

### nginx

| Ситуация | Уровень |
|---|---|
| `nginx -t` падает | **блокер** |
| nginx нет в PATH | `!!` |
| другой конфиг уже держит `/recording/` с `proxy_pass` | **блокер** — nginx возьмёт первый блок |

### answers

| Ситуация | Уровень |
|---|---|
| дубль ключа | **блокер** — последнее значение молча перекрывает первое |
| неизвестный ключ (опечатка) | `!!` |
| `DOMAIN` пуст | **блокер** |
| `DOMAIN` со схемой `https://` | **блокер** |
| `DOMAIN` = заглушка | `!!` |
| `PLUGIN_DIR` = `/`, `/etc`, `/usr`, `/root`, `/var`, `/tmp` | **блокер** |
| `ADOPT_EXISTING` + `PUBLISH_LOOPBACK_PORTS=true` | `!!` |

### Ресурсы

| Ситуация | Уровень |
|---|---|
| RAM меньше `2 ГБ × воркеры + 2 ГБ` | `!!` |
| свободно меньше 5 ГБ на `/` или `/var/lib/docker` | `!!` |

## Разрешение конфликта учётных записей

Если проверка сказала «пароль не подходит» или «пароль неизвестен», есть три
выхода. Инструмент показывает состояние и делает выбранное:

```bash
# 1. Посмотреть, что есть на сервере (ничего не меняет)
bash tools/resolve-bot-accounts.sh --users bot1 --inspect

# 2. Задать известный пароль существующим аккаунтам и записать в answers
bash tools/resolve-bot-accounts.sh --users bot1 \
     --reset 'НовыйПароль123!' --set-env /root/answers.env

# 3. Удалить аккаунты, чтобы установщик создал их заново
bash tools/resolve-bot-accounts.sh --users bot1 --delete
```

Пароль меняется через admin API Synapse (`PUT /_synapse/admin/v2/users/<user>`),
старый пароль не нужен. Нужен admin access token: скрипт ищет его в таблице
`access_tokens` (учётка с `admin = 1`) либо принимает `ADMIN_TOKEN=...`.

Что важно знать про удаление:

* деактивация завершает сессии бота и стирает устройство с E2EE-ключами;
* каталог `profile-spk` на диске остаётся, но бот вступит в комнаты как новое
  устройство — участники увидят новую сессию;
* записанные файлы не затрагиваются.

Поэтому `--reset` предпочтительнее: он меняет только пароль и сохраняет
устройство бота, то есть E2EE-сессия остаётся прежней.

## Тесты проверок

Каждая проверка — обычная функция над данными, поэтому проверяется на фикстурах
без Docker. Сценарии, которые обязаны совпадать с ожиданием:

| # | Сценарий | Ожидание |
|---|---|---|
| A | аккаунт есть, пароль неверный | блокер |
| B | аккаунт есть, пароль верный | пропуск |
| C | аккаунта нет, пароль пуст | блокер |
| D | аккаунта нет, пароль задан | пропуск, предупреждение |
| E | аккаунт есть, пароля нет вообще | блокер |
| F | Synapse недоступен | пропуск, предупреждение |
| G | бот = `ADMIN_USER` | блокер |
| H | порт занят чужим процессом | блокер |
| I | порт свободен | пропуск |
| J | дубль ключа в answers | блокер |
| K | опечатка в ключе | пропуск, предупреждение |
| L | `DOMAIN` со схемой | блокер |
| M | `PLUGIN_DIR=/etc` | блокер |
| N | чистый answers | пропуск |
| O | observer старой сборки | блокер |
| P | штатный observer | пропуск |
| Q | шаблон падает | блокер |

Фейковый Synapse для сценариев A–F отвечает на `/profile` и `/login` так же,
как настоящий, включая `M_FORBIDDEN` на неверный пароль.

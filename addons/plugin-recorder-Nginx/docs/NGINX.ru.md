# Плагин за nginx вместо nginx

nginx нужен только **инсталлятору** — он публикует маршруты через labels
контейнеров. Отдавать трафик — обычная задача обратного прокси, и nginx с ней
справляется.

## Контракт

| Путь | Бэкенд | Что делать с префиксом |
|---|---|---|
| `/recording` и `/recording/*` | `rec-controller:8765` | срезать `/recording` |
| `/recordings` и `/recordings/*` | `rec-portal:8899` | срезать `/recordings` |

Готовый конфиг — [`nginx.example.conf`](../nginx.example.conf). Вставь его три
блока `location` в тот `server { }`, который уже отдаёт Element Web, затем:

    nginx -t && systemctl reload nginx

## Доступность бэкендов

Хостовый nginx увидит бэкенды только через опубликованные порты:

    PUBLISH_LOOPBACK_PORTS="true"     # по умолчанию — 127.0.0.1:8765 и :8899

Если nginx в контейнере на той же docker-сети, оставь `false` и обращайся по
именам сервисов:

    proxy_pass http://rec-controller:8765/;
    proxy_pass http://rec-portal:8899/;

Без опубликованных портов хостовый nginx получит `connection refused` — это
первое, что надо проверить, если `/recording/health` не отвечает.

## Три вещи, на которых легко ошибиться

1. **`proxy_pass` обязан заканчиваться на `/`.** Именно этот слэш срезает
   префикс. Без него контроллер получит `/recording/api/record/start` и
   ответит 404, хотя сам маршрут выглядит рабочим.
2. **Никогда не `proxy_pass http://127.0.0;`.** nginx не запустится с
   `host not found in upstream` и уронит весь vhost — и все сайты на нём.
3. **`proxy_read_timeout` поднимать не нужно.** `/api/record/stop` сразу
   отдаёт `202`, финализация идёт асинхронно в воркере и паблишере, а UI
   опрашивает `/api/record/status`.

Приоритеты nginx не нужны: побеждает самый длинный префикс, поэтому
`location /recording/` не перехватывает `/recordings/` — ровно то, что в
варианте с nginx решается приоритетами 100/90.

## Проверка

С любой машины, откуда виден домен — доступ к серверу не нужен:

    curl -s -o /dev/null -w '%{http_code}\n' https://<domain>/recording/health
    # 200 или 401 -> маршрут, стрип префикса и бэкенд в порядке
    # 404         -> префикс /recording не срезан
    # 502         -> бэкенд лежит или порт не опубликован

    curl -s -o /dev/null -w '%{http_code}\n' https://<domain>/recordings/
    # не-200 для анонима, как и ожидается

    curl -s https://<domain>/config.json | jq '.modules'
    # должен содержать модуль рекордера, иначе кнопка не загрузится

## Модель доступа

| Действие | Требование |
|---|---|
| Запуск / остановка записи | уровень в комнате >= `RECORDING_MIN_POWER_LEVEL` (по умолчанию 50) |
| Просмотр и скачивание записей комнаты | уровень в комнате >= `RECORDINGS_MIN_POWER_LEVEL` (по умолчанию 50) |
| Все записи сервера | админ Synapse, через `/_synapse/admin/v2/users` |

Кнопка «Запись» отображается всем участникам комнаты; проверка прав — на
сервере. Уровень, посчитанный в браузере, используется только для текста
ошибки и никогда не считается доверенным: `POST /api/record/start` сам
разрешает вызывающего через `/_matrix/client/v3/account/whoami`, читает
`m.room.power_levels` и отвечает `403`.

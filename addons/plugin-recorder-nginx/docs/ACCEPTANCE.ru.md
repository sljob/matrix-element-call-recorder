# Приёмка на отдельном тестовом сервере

Эти проверки не заменяются зелёными unit/integration tests. Потребуются работающие Synapse, Element Web, Element Call, LiveKit и **host Nginx**. Сначала используйте отдельный сервер и отдельный bot/device/profile, а не действующий стек с предыдущими серверными правками.

## До установки

1. Звонок между двумя обычными пользователями работает без плагина: оба видят и слышат друг друга.
2. Используемый recorder image уже существует локально и совместим с монолитным runtime. Никаких `docker build` или `pull` установщик не выполняет.
3. Настроены loopback endpoint Synapse/Call/LiveKit, домен резолвится из recorder Chromium. При частном CA указан актуальный leaf SPKI.
4. Файл Element config действительно читается текущим Element. В конфигурации нет другого record module, а в Nginx нет конфликтующих `/recording` и `/recordings` locations.

## Сценарий

- Установить через `--install`. Проверить оба сервиса `docker compose -p <project> -f <plugin_dir>/compose.json ps` и `nginx -t`.
- Обновить Element; убедиться, что модуль загружен без Module API error.
- Создать приватную зашифрованную комнату, пригласить второго пользователя. Включить камеры и микрофоны обоих.
- Пользователь с нужным power level и правом invite нажимает Запись. Бот приглашается автоматически; ручная выдача ему администратора не требуется.
- Записать не менее 45 секунд с голосом, движением, выключением/включением камеры и демонстрацией экрана.
- До stop архив не содержит незавершённый файл. Статус не колеблется idle/recording.
- Нажать Стоп один раз. Observer закрывается, FFmpeg завершается, появляется MP4 с duration и двумя потоками (H264/AAC для обычного A/V-звонка), затем MP3/JPG и metadata commit.
- Открыть `/recordings/`, войти Matrix-аккаунтом. Одна комната — одна группа; одна запись — один видеоплеер, аудиоплеер и две ссылки скачивания. Проверить реально изображение второго участника и его голос, не только ffprobe.
- Перемотка видео работает: запрос Range возвращает 206. Чужой пользователь вне комнаты не видит запись и получает 403 на прямой файл.
- Второй start той же комнаты не создаёт второй observer; start другой комнаты при занятом worker возвращает ошибку.
- После stop бот очищает активное участие в звонке. Общее членство в Matrix-комнате может сохраняться.
- Выполнить `--repair` после stop. Bot/device/profile неизменны, архив сохранён, повторная запись воспроизводится с видео и звуком.
- Убить worker во время тестовой записи: после перезапуска незавершённый файл не публикуется автоматически как успешная запись. Новый start доступен после состояния error. Профиль сохранён.
- Прервать публикацию после создания `.done`, перезапустить worker: публикация завершается один раз, исходник остаётся.
- Проверить ошибку неправильного Nginx vhost: установка должна отказаться без изменения конфигурации. Проверить rollback через конкретный backup.

## Что фиксировать

Commit источника, digest recorder image и backend image, версии Element Web/Call/Synapse/LiveKit, результат каждого пункта, длительность и codecs MP4. В журнал не включать токены, пароли и содержимое профиля.

Release candidate становится подтверждённым релизом только после успешных fresh-install, repair и реального E2EE A/V-теста. На момент сборки эти пункты не выполнены в доступной среде.

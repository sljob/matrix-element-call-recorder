# 3.1.0 — пересборка Nginx-издания по итогам разбора стенда

Релиз-кандидаты 3.0.0-rc2..rc4 в ветке `nginx-recorder-v3` не ставились на живом
сервере: установщик падал или ставил неработоспособную цепочку. Здесь учтена
каждая причина из журналов стенда (05.11 — 11.11). Изменения касаются
архитектуры фронт-слоя, а не косметики.

## Устранённые причины отказов

**1. `KeyError: 'LIVEKIT_KEY'` и вечный рестарт контроллера.**
Контроллер монолита читал `os.environ["LIVEKIT_KEY"]` на импорте. Плагину LiveKit
не нужен вовсе. Новый `src/controller/app.py` читает все переменные лениво, не
обращается к LiveKit и всегда отдаёт `200` на `/api/health`, даже когда worker
недоступен — причина в поле `diagnostics`, а не в падении процесса.

**2. Два контроллера в одной сети.**
В контуре одновременно жили `rec-controller` и `recording-controller`; nginx
проксировал то в один, то в другой — отсюда 404/500 на `/recording/api/`.
Теперь единственный контроллер — сервис `rec-controller`. Посторонний
`recording-controller` распознаётся preflight-проверкой как блокер.

**3. `location` в `http{}` и «nginx -t failed».**
Файл со `location` в `conf.d/` парсится в контексте `http{}`, отсюда
`"location" directive is not allowed here`. Сгенерированные фрагменты со
`location` теперь всегда лежат в `includes/` и подключаются только из `server{}`.
Ошибка воспроизведена в тестах и закрыта.

**4. Пустой или чужой `:18085`.**
Каталог конфигов монтировался в контейнер только для чтения, правки «изнутри»
не применялись, файл уходил в карантин, порт оставался без владельца.
Контейнер `record-plugin-static` пересоздаётся установщиком с обоими
bind-mount'ами (`conf.d` — rw, статика — ro), а расхождение монтирований
определяется по `docker inspect`, а не по факту «контейнер запущен».

**5. Ожидание Traefik.**
Установщик требовал Traefik и падал с `Traefik container not found`. Traefik
больше не упоминается: режим по умолчанию — собственный nginx-контейнер,
второй режим — интеграция в существующий nginx (контейнер или хостовый бинарь).

**6. `trap ERR at line N` вместо диагностики.**
В `install.sh` стоит trap, который печатает команду, код возврата, строку,
файл и каталог, и подсказывает снять `--doctor`.

**7. Обрезка пути API при проксировании.**
`proxy_pass` без завершающего слэша превращал `/recording/api/record/start` в
`/recording/api/record/start` на бэкенде и давал 404. Зафиксировано тестом.

**8. Неоднозначный `server{}` во фронт-конфиге.**
Вставка `include` в первый попавшийся `server{}` давала 404 при чистом
`nginx -t`. Теперь вставка выполняется только если найден ровно один `:443`
server{} для домена; иначе печатается готовая строка для ручной вставки.

## Новые возможности

- `--doctor` — глубокая диагностика цепочки без изменений.
- `--verify` — сквозная проверка всех звеньев, пригодная для cron/CI.
- Preflight с кодами (`PORT`, `NET`, `CNT`, `NGX`, `OBS`, `ANS`, `RES`) и
  готовой командой исправления в каждом блокере.
- `GET /api/version` и `GET /api/health` у контроллера.
- Идемпотентность: повторный `--install`/`--repair` не плодит блоки и не
  ломает уже настроенные маршруты.
- Проверка `vendor/p63-observer.js` перед сборкой: обрезанный файл — блокер,
  а не падение сборки на 10-й минуте.

## Проверено в этом релизе

- `nginx -t` и живые HTTP-запросы для режима `standalone` (200 на `/healthz`,
  `/recording/`, `/recording/record-button.js`, 308 на `/recording`).
- `nginx -t` и живые запросы для режима `external` (include в чужой `server{}`).
- Негативный тест: `location`-файл в `conf.d/*.conf` даёт ровно ту ошибку,
  которую он и должен давать — и наш установщик так не делает.
- Контроллер без переменных окружения: `200` на `/api/health`, `401` на
  `/api/record/start` без токена.

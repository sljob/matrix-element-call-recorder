# Начать с этого файла — RC3

1. Сохраните snapshot. Не запускайте старые 01–30 fix-скрипты из dev bundle. RC3 не разворачивает платформу заново. Если nginx -t уже выдаёт location not allowed here, восстановите последний корректный Nginx-конфиг из вашей резервной копии; не вставляйте include во все vhost.
2. Распакуйте RC3 в НОВЫЙ каталог, не поверх старого дерева. Проверьте SHA256SUMS. Реальный answers храните отдельно и не присылайте файл с паролями.
3. В answers задайте настоящий recorder_image (лучше immutable ID/digest), адреса реальных сервисов и активный nginx_server_config. На отдельной платформе из этой переписки Synapse обычно опубликован на 18008, LiveKit на 17880, Call на 8090 — это не универсальные значения. Проверяйте свой Compose. Фиктивный python /health и stub recorder исключаются.
4. Штатная проверка (выполнять root):

    bash tools/preflight.sh /root/recorder-nginx.answers.json

Она ничего не устанавливает. FAIL содержит подсказку. Наличие другого бот-аккаунта в Synapse само по себе не конфликт; конфликтуют одновременно запущенные recorders с тем же аккаунтом/профилем. На fresh install с ещё не созданным ботом штатный check может закончиться сообщением о неуспешном входе; автоматическое создание через явно указанный shared secret возможно только --install.
5. Для первой завершённой установки:

    bash install.sh --install /root/recorder-nginx.answers.json

Для ранее УСПЕШНО установленного проекта, где есть compose.json и identity.json:

    bash install.sh --repair /root/recorder-nginx.answers.json

Не создавайте эти файлы вручную, чтобы обойти preflight. Если прошлые попытки оставили лишь static/mock — это не установленный RC2. Не удаляйте такой каталог автоматически: переместите/сохраните его отдельно и разберите связанные включения Nginx до новой установки. Не выбирайте новый project, оставив конфликтующий старый worker.
6. Успех установки требует Nginx -t, readiness контейнеров, HTTP GET настоящего JS по HTTPS, наличие Module API entry в реальном /config.json и настоящие service identities backend/worker. Установка откатывает управляемые конфиги при провале postcheck. Неудачный TLS/DNS не обходите флагом -k.
7. Обновите Element Web, убедитесь, что modules содержит /modules/recorder-nginx/index.js и модуль загружен. Затем проведите настоящий звонок двух пользователей с камерами и голосом; запишите и остановите, проверьте изображение и звук в MP4. Только этот шаг доказывает работоспособность медиазахвата. См. docs/ACCEPTANCE.ru.md.

Сборка остаётся RC: исправления установщика проверены автоматически, но чистая VM-установка и E2EE A/V-приёмка на вашем сервере ещё не выполнены.

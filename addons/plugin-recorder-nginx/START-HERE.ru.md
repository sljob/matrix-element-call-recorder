# RC4 — начать здесь

Прочитайте CHANGELOG-RC4.ru.md: причина ложного NGINX-ACTIVE устранена в исходниках. Не запускайте прежние серверные fix-скрипты и не удаляйте vhost ради обхода ошибки.

1. Сохраните snapshot и резерв Nginx. Распакуйте RC4 в новый каталог, не поверх RC3. Проверьте SHA256SUMS. Храните answers отдельно с правами 0600.
2. Для платформы из отчёта задайте synapse_url=http://127.0.0.1:18008 и livekit_internal=127.0.0.1:17880. На другом сервере сверяйте реальные Docker port bindings. Укажите существующий проверенный recorder_image. Отсутствующий образ не скачивается и не строится автоматически.
3. От root выполните:

    bash tools/preflight.sh /root/recorder-nginx.answers.json

FAIL нельзя игнорировать: вывод содержит причину и подсказку. Ранее выданный нестандартный custom-preflight не использовать. Разные аккаунты Synapse могут сосуществовать; один device/profile не должен одновременно использоваться двумя рекордерами.
4. Для первой завершённой установки:

    bash install.sh --install /root/recorder-nginx.answers.json

Только для ранее успешно установленного проекта с настоящими compose.json и identity.json:

    bash install.sh --repair /root/recorder-nginx.answers.json

Не создавайте identity/compose вручную для обхода проверки. Если бот ещё не создан, check откажет на login; автоматическое создание через явно заданный shared secret возможно только --install. Существующие пароли не сбрасываются.
5. До теста записи сайт должен открывать настоящий Element Web, не welcome Nginx. Проверьте обычный звонок двух участников. После установки проверьте загрузку Module API ui/index.js, запись и остановку, затем изображение и звук нового MP4.

Это исправленный RC, а не подтверждённый production-релиз. HTTP readiness и автоматические тесты не заменяют реальный E2EE A/V-тест.
